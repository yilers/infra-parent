# File 文件服务规划

## 目标

`file` 为业务系统提供统一的文件上传、下载和存储能力。业务系统依赖 `file-core` 时可直接获得本地服务与 HTTP 接口；独立部署后只通过 `file-api` 交换文件标识和元数据。

## 模块结构

```text
file
├── file-api
└── file-core
```

- `file-api`：服务契约、请求响应对象和扩展接口。
- `file-core`：控制器、服务实现、持久化、权限校验和存储框架适配。
- `file-start`：需要独立部署时再创建。

包根路径为 `io.github.yilers.file`。

## 功能范围

第一阶段提供普通上传、流式下载、文件查询、删除、租户隔离、应用隔离和文件访问权限，支持本地存储及一种对象存储。

第二阶段增加文件哈希、秒传、手动分片上传、上传断点续传、HTTP Range 下载、失败补偿、孤立文件清理和过期分片清理。

## 存储框架

计划使用 `x-file-storage` 统一适配本地、MinIO 和对象存储。接入前必须验证其与 Spring Boot 4、JDK 25、Jakarta Servlet 和当前依赖版本的兼容性。

`x-file-storage` 只允许出现在 `file-core`，其 `FileInfo` 等类型不得进入 `file-api`。文件记录钩子由 `file-core` 实现，并保存到项目自己的数据表。

## 数据规划

```text
file_record    文件元数据和上传状态
file_part      手动分片上传记录
```

后续可选：

```text
file_storage         动态存储平台配置
file_operation_log   文件操作审计
```

文件记录至少保留租户、应用、存储平台、对象键、原始名称、MIME 类型、大小、哈希、上传人、业务类型和业务标识。业务表只保存 `fileId`，不持久化易变化的完整访问地址。

## 安全边界

- 上传、分片和管理接口使用 Sa-Token 登录或权限注解。
- 下载和删除除接口权限外，还必须校验租户、应用、上传人及关联业务数据的访问权限。
- 公开文件必须显式标记，私有文件通过鉴权下载或短期签名地址访问。
- 秒传可复用物理对象，但必须为当前租户创建独立的逻辑文件记录。

## 独立部署

独立部署时新增 `file-start`。文件流通过 HTTP 或对象存储直传，RPC 只负责文件信息查询、业务绑定和状态操作。认证中心提供的 token 由 `common-auth` 识别，远程权限查询由启动器中的 UPM 适配器提供。
