# Notice 通知服务规划

## 目标

`notice` 统一承载短信、邮件、钉钉和飞书通知，屏蔽具体厂商接口差异，并保证通知任务可追踪、可重试和幂等。

## 模块结构

```text
notice
├── notice-api
└── notice-core
```

- `notice-api`：通知服务契约、渠道枚举和请求响应对象。
- `notice-core`：模板、任务、记录、异步调度和渠道提供者实现。
- `notice-start`：需要独立部署时再创建。

包根路径为 `io.github.yilers.notice`。

## 服务规划

```text
NoticeService      模板解析与多渠道编排
SmsService         短信发送
MailService        邮件发送
OaNoticeService    钉钉与飞书通知
```

业务模块只使用上述稳定接口，不直接依赖厂商 SDK 或第三方框架的工厂、请求对象和枚举。

## 渠道范围

第一阶段只规划以下渠道：

```text
SMS       短信
MAIL      邮件
DINGTALK  钉钉
FEISHU    飞书
```

微信公众号、小程序和企业微信应用消息在产生真实需求后通过 Provider 扩展。

## 数据规划

```text
notice_template   通知模板
notice_task       持久化发送任务
notice_record     每次真实发送记录
```

不同租户需要维护自己的厂商账号时再增加：

```text
notice_provider   渠道与服务商配置
```

一条 `notice_task` 对应一个渠道和一个接收目标。群发及多渠道通知拆分为多条任务，便于单独重试和审计。任务使用幂等键防止业务重试导致重复发送。

## 异步与重试

业务事务只负责写入待发送任务。后台线程提交事务后抢占任务，同步调用渠道 Provider，再更新任务状态并写入发送记录。不得依赖仅存在于内存线程池中的任务作为可靠通知来源。

第一版可使用数据库任务表和现有动态线程池；以后改用消息队列时保持 `notice-api` 不变。网络调用期间不持有数据库事务，多实例通过条件更新和乐观锁避免重复发送。

## Sms4j选型

Sms4j 作为短信、邮件和办公平台消息的候选发送引擎。鉴于 4.x 正在重构，当前不引入 Sms4j 3.x，也不在接口中使用 Sms4j 类型。4.x 稳定后重新验证 Spring Boot 4、JDK 25、邮件模块和各渠道兼容性。

## 安全边界

- 业务发送优先通过后端 Service 调用，不向前端开放任意收件人和任意正文的群发接口。
- 模板、任务、记录和测试发送等管理接口使用权限注解。
- 手机号、邮箱、密钥和正文中的敏感信息按用途加密或脱敏，并设置合理的数据保留期限。
